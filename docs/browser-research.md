# 浏览器研究服务

## 默认模式

`RESEARCH_BACKEND=browser` 随应用启动持久化执行器，使用 Playwright 打开独立 Chrome。它不依赖聊天会话在线，不接管用户已有浏览器，不复用个人登录 Cookie。

需要本机 Google Chrome、后端依赖、可用的图片理解和中文归纳模型。当前主要验证环境为 Windows；Docker 镜像仍需自行补齐浏览器和系统依赖。

```ini
RESEARCH_BACKEND=browser
BROWSER_SERVICE_ENABLED=true
BROWSER_CHANNEL=chrome
BROWSER_HEADLESS=true
WORKER_ENABLED=true
```

## 工作方式

1. 从原图与 OCR 提取项目名、仓库链接和检索词。
2. 优先在浏览器核对明确的 GitHub 仓库链接；仍有未知项目时搜索网页。项目名独立检索，避免作者拼写错误使查询过窄。
3. 仅匹配截图实际介绍的项目，排除依赖和同名无关项目；单图项目数量不固定截断。
4. 打开真实仓库和 Releases 页面，保存正文、URL 与截图。
5. 基于已读取页面生成中文说明，校验原文引用，获取仓库元数据，再按自动确认设置关联项目。

图片、OCR、README 和网页均为不可信资料，不执行其中的操作指令。浏览器只访问允许的公开 HTTPS 地址，禁用下载，不通过模型文本执行命令。

## 限流与故障

- 普通页面后默认间隔 15 秒，搜索页面后默认间隔 30 秒。
- HTTP 403/429 触发全队列冷却，初始至少 15 分钟，重复限流指数退避；优先遵守更长的 Retry-After。
- 冷却及请求间隔保存到数据库，重启不会清除；期间不领取其他浏览器任务继续访问同一网站。
- 每页读取后保存来源和搜索结果链接，中断后继续使用已有证据。
- 网站验证码或验证阻断会停止服务并显示原因，不绕过验证。
- AI 日额度不足保留进度等待恢复。额度按 UTC 日期计数，请同时关注服务供应商账单。

任务中心显示在线、冷却、执行阶段及实际浏览器尝试次数。网页与元数据 API 的限流是不同机制，配置 GitHub Token 不会取消网页限流。

## 兼容模式

`RESEARCH_BACKEND=computer_use` 保留授权桌面会话的领取与回传协议，需要会话接手；详见 [桌面执行协议](computer-use-agent.md)。`RESEARCH_BACKEND=deepseek` 才使用旧搜索 API 模式，不会自动回退启用。

已保存来源的中文补全和用途分类直接使用模型归纳，无需重复搜索网页。定时高星项目发现是独立 GitHub API 功能。
