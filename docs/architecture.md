# 架构与开发说明

GitHub Lens 将项目截图整理为带来源的 GitHub 项目资料库，当前面向单管理员、本机单 Worker 部署。

## 技术组成

| 模块 | 技术与职责 |
| --- | --- |
| 工作台 | React 19、TypeScript、Vite；项目、导入、发现、任务及手机上传 |
| API | FastAPI、SQLAlchemy；鉴权、上传会话、资料、引用及分类管理 |
| 存储 | 默认 SQLite；可配置 PostgreSQL；图片与浏览器截图使用本地文件 |
| OCR | PaddleOCR 3.x，默认使用 v5 mobile CPU 模型 |
| 网页研究 | Playwright 与独立 Chrome，持续领取队列、网页核对与来源保存 |
| 中文资料 | 兼容 Chat Completions 的模型；图片理解、引用归纳及用途分类 |
| 仓库信息 | GitHub API 获取已核实仓库元数据、README、Release；另有高星发现 |

## 数据流程

上传 → OCR → 图片理解 → 浏览器检索 → 核实仓库 → 整理带引用的中文资料 → GitHub 元数据入库 → 用途分类与检索。

公开源码不包含任何个人资料库、上传图片、凭证或本地研究记录。首次运行创建空数据库，并在本机设置管理员密码。

主要表包括 repositories、images、image_links、image_research、jobs、upload_sessions、project_trash 和 project_organization。项目回收站仅改变可见范围，保留笔记、标签、截图关联与分类。

## 中文归纳与分类

中文资料完整度要求带引用的中文概述、主要功能和适用场景。特色、部署要求及日期没有可靠证据时留空，不推断独立创新性。原始简介和 README 仍可查看。

引用允许空白、HTML/Markdown 纯格式差异，保存实际原文中的连续片段，拒绝实质文字变化。刷新未得到完整中文资料时保留既有中文分析，并显示更新状态。

资料整理优先使用已保存的 README、原始简介和网页证据。项目最多属于三个主要用途，另保存中英文检索关键词；手动修改的分类和关键词不会被自动整理覆盖。

检索覆盖项目名、中文概述、功能、场景、关键词、标签、笔记和用途，支持空格分隔的多词组合、近义术语与相关度排序。当前为关键词检索，并非向量语义搜索。

## 队列与恢复

数据库保存任务状态、阶段、来源及逐项目进度。网页任务具有独占租约和心跳；取消或被新任务取代后，旧执行器不能覆盖新结果。配额不足等待恢复，单项生成失败不阻断整库其他项目。

当前必须保持 Uvicorn `--workers 1`。多 Worker、分布式队列、正式数据库版本迁移、导入历史完整分页、自动保留期和涨星趋势榜属于后续范围。

## 验证

后端测试使用临时数据库；浏览器测试使用独立的测试数据库和测试密码，禁止指向个人资料库。真实联网烟测需要另行配置，并会消耗对应服务额度。

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q --import-mode=importlib
cd frontend
npm run build
npx playwright test
```

查询列表仅提取所需字段，导入批次合并读取图片与研究状态；来源正文按需读取。新增索引采用幂等创建，复杂表结构变更仍需正式迁移流程。
